# Module Specification

Module: nfs_mamont::serializer::server::nfs::link
Rust File: src/serializer/server/nfs/link.rs

---

## 1. Dependencies

- **`std::io` / `std::io::Write`**: Provides the `Write` trait, which is the abstraction used for the output destination (e.g., a TCP stream or a buffer). The `io::Result` type is used for error propagation.
- **`crate::serializer::files`**: Supplies specific XDR serialization primitives for file system entities, specifically `file_attr` (for serializing file attributes) and `wcc_data` (for serializing Weak Cache Consistency data).
- **`crate::serializer::option`**: Provides a generic helper to serialize `Option<T>` types according to XDR rules (a boolean discriminator followed by the value if present).
- **`crate::vfs::link`**: Defines the domain-specific data structures `link::Success` and `link::Fail`. These structures represent the logical outcome of a VFS link operation and serve as the input data for serialization.

---

## 2. Mechanics

Intent:
- To convert the high-level Rust structures representing the result of an NFSv3 `LINK` procedure (`link::Success` and `link::Fail`) into the binary XDR format required for network transmission.

Inputs:
- `dest`: A mutable reference to a type implementing the `Write` trait. This is the sink where the serialized bytes will be written.
- `arg`: Either a `link::Success` or `link::Fail` structure containing the file attributes and directory Weak Cache Consistency (WCC) data resulting from the link operation.

Outputs:
- `io::Result<()>`: Indicates the success or failure of the write operations. Returns `Ok(())` if serialization completes successfully, or an `Err` if an I/O error occurs.

Steps:
1. **Serialize File Attributes**: The function calls the `option` serializer, passing `arg.file_attr`. If the attribute is `Some`, it invokes the closure `file_attr(dest, &attr)` to write the attribute data to `dest`.
2. **Serialize Directory WCC Data**: The function calls `wcc_data(dest, arg.dir_wcc)` to serialize the Weak Cache Consistency data for the directory where the link was created. This writes the pre-operation and post-operation attributes to `dest`.

Edge Cases:
- **Missing Attributes**: If `arg.file_attr` is `None`, the `option` serializer writes a discriminant indicating absence (false) and skips the attribute serialization.
- **WCC Data**: The `wcc_data` serializer handles the internal optionality of `before` and `after` attributes within the `WccData` struct.

Complexity:
- **Time**: O(N), where N is the size of the serialized data (fixed size for attributes, variable for file handles/paths within WCC data).
- **Space**: O(1) auxiliary space, as data is written directly to the output stream.

Determinism:
- Deterministic

---

## 3. Dependency Mechanics

- **`crate::serializer::files::file_attr`**: Serializes the `file::Attr` structure (metadata like mode, size, uid, gid, etc.) into XDR format.
- **`crate::serializer::files::wcc_data`**: Serializes the `vfs::WccData` structure, which contains optional pre-operation (`WccAttr`) and post-operation (`Attr`) attributes for cache consistency.
- **`crate::serializer::option`**: Encodes the `Option` type as a boolean (1 for present, 0 for absent) followed by the encoded value if present.

---

## 4. Data Model

Entities:
- **`link::Success`**: Represents the successful result of a link operation. Contains `file_attr` (post-op attributes of the linked file) and `dir_wcc` (WCC data for the directory).
- **`link::Fail`**: Represents the failed result of a link operation. Contains `file_attr` (attributes if available) and `dir_wcc` (WCC data for the directory). Note: The error code itself is handled outside this module.

Relations:
- Both `Success` and `Fail` entities share an identical serialization layout regarding the data fields: `file_attributes` followed by `dir_wcc`.

Global Invariants:
- The order of fields in the XDR output must strictly follow the NFSv3 specification: `file_attributes` (optional) then `dir_wcc`.

---

## 5. Error Model

Error Types:
- **`std::io::Error`**: Represents any I/O error that occurs during writing to the `dest` buffer or stream.

Error Propagation Strategy:
- Propagation. The module uses the `?` operator to immediately return any `io::Error` generated by the underlying serializers or the `Write` trait implementation.

Recoverability:
- Not applicable at this layer. The module is a pure serializer; if writing fails, the error is propagated up the stack to the caller (likely the RPC handler) to manage the connection state.

Panics:
- **Allowed**: No
- **Conditions**: The code itself does not panic. However, if the underlying `Write` implementation panics, or if the specific serializers (`file_attr`, `wcc_data`) panic, that panic will propagate through this module.

---

## 6. Traits

- **`std::io::Write`**: Used as a constraint (`impl Write`) on the `dest` argument, allowing the module to write to any target (buffers, sockets, files).

## 7. Overview

This module is used in order to serialize the results of the NFSv3 `LINK` procedure (creating a hard link) into the XDR format required for network transmission. It acts as a translation layer between the internal Virtual File System (VFS) representation of operation results and the standardized wire format defined by the NFS protocol.

The system contains a set of serializers that map VFS domain objects (like `Success` and `Fail` structs) to byte streams. The `LINK` procedure specifically requires returning the attributes of the file that was linked and Weak Cache Consistency (WCC) data for the directory containing the new link. This is crucial for clients to update their caches without needing to issue separate `GETATTR` or `LOOKUP` calls immediately after the operation.

A typical usage scenario of the system involves the server processing a `LINK` request via the VFS layer. The VFS layer returns a `Result<Success, Fail>`. Based on the result, the RPC handler invokes either `result_ok` or `result_fail` from this module, passing a network socket buffer as the destination. The module writes the specific XDR-encoded bytes representing the file attributes and directory state changes to the buffer, which are then sent back to the NFS client.

Inside the system the following things happen and they use:
1. The `option` serializer handles the conditional presence of file attributes.
2. The `file_attr` serializer converts the Rust struct representing file metadata into XDR integers and opaque data.
3. The `wcc_data` serializer ensures that the directory's state before and after the operation is correctly encoded to maintain cache coherency across the network.
