### Mechanism: NFS Status Serialization (`error`)

Intent:
- To serialize a Virtual File System (VFS) error code into the XDR format required for the NFS status field (the union discriminant in an NFS response).

Inputs:
- `dest`: A mutable reference to a type implementing the `Write` trait, serving as the byte sink.
- `stat`: An instance of `vfs::Error`, representing the specific NFS status code (e.g., success or specific failure).

Outputs:
- `io::Result<()>`: Indicates successful completion of the write operation or an I/O error.

Steps:
1. Invoke the `variant` helper function, passing the destination writer and the `stat` error code.
2. The `variant` function converts the `vfs::Error` enum into its primitive integer representation (likely `u32`) and writes it to the destination in Big Endian format.
3. Return the result.

Edge Cases:
- Relies on the `variant` function to handle the specific mapping of `vfs::Error` variants to their integer values. If `vfs::Error` cannot be converted to a primitive (e.g., if it were not `ToPrimitive`), the underlying dependency would handle the error.

Complexity:
- Time: O(1) — Writes a fixed-size integer.
- Space: O(1) — No auxiliary allocation.

Determinism:
- Deterministic. The same error code produces the exact same byte sequence.

## 7. Overview

This module is used in order to **organize the serialization logic for the NFSv3 protocol** and provide a **shared utility for serializing NFS status codes**.

The system contains a large number of NFSv3 procedures (e.g., `READ`, `WRITE`, `CREATE`, `MKDIR`, etc.). To manage this complexity, the serialization logic for each procedure is separated into its own submodule (e.g., `nfs::read`, `nfs::write`). This module acts as the parent namespace for these procedure-specific serializers. It aggregates them, making them accessible via a unified path (e.g., `nfs_mamont::serializer::server::nfs::read`).

Furthermore, every NFSv3 response begins with a status code (an integer indicating success or failure type). Instead of duplicating the logic to serialize this status code in every procedure submodule, this module provides the `error` function. This function acts as a centralized serializer for the `vfs::Error` enum, converting it into the XDR integer format required by the protocol.

A typical usage scenario of the system involves the RPC response builder. When constructing a reply, the builder first determines the status of the operation (Success or Fail). It calls the `error` function from this module to write the status code into the buffer. Then, based on the procedure type, it dispatches to the appropriate submodule (e.g., `nfs::read::result_ok`) to serialize the specific payload body.

Inside the system the following things happen and they use **the `variant` primitive** to ensure the status code is correctly encoded as a 32-bit big-endian integer. The submodules declared within this file handle the complex, procedure-specific data structures (like file attributes, directory entries, and weak cache consistency data), relying on this parent module only for the common status serialization utility.
