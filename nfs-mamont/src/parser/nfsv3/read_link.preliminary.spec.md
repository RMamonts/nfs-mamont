## 2. Mechanics

Here you need to list the key mechanisms implemented in this module. 
A key mechanism can be identified by its semantic complexity and/or its public visibility.

Intent:
- To deserialize the arguments for the NFSv3 `READLINK` procedure from a raw byte stream into a structured `read_link::Args` object.
- To delegate the low-level parsing of the file handle to the specialized `file` module while handling the result construction locally.

Inputs:
- `src: &mut impl Read`: A mutable reference to a byte stream containing the serialized arguments for the `READLINK` operation. According to the NFSv3 protocol, this consists of a file handle.

Outputs:
- `Result<read_link::Args>`: A Result containing the parsed arguments on success, or a `parser::Error` on failure.

Steps:
1. **File Handle Parsing**: The function calls `file::handle(src)` to read the file handle from the stream. This involves reading a length prefix and the subsequent handle bytes, validating the length against `NFS3_FHSIZE`.
2. **Argument Construction**: If the file handle is parsed successfully, it is wrapped in the `read_link::Args` structure: `read_link::Args { file: parsed_handle }`.
3. **Return**: The `Args` structure is returned wrapped in `Ok`. If `file::handle` returns an error, that error is propagated immediately using the `?` operator.

Edge Cases:
- **Invalid File Handle**: If the stream contains a file handle with a length that does not match `NFS3_FHSIZE`, `file::handle` will return `Error::BadFileHandle`, which propagates from this function.
- **Unexpected End of Stream**: If the stream ends before the file handle can be fully read, an `IO` error is propagated.

Complexity:
- Time: O(N), where N is the size of the file handle (fixed at 64 bytes in NFSv3, plus the length prefix).
- Space: O(N), for the allocated `file::Handle` structure.

Determinism:
- Deterministic. Given the same input byte sequence, the function will always produce the same `read_link::Args` structure or the same error.

This module is used in order to deserialize the specific arguments required by the NFSv3 `READLINK` procedure from the network byte stream into a format consumable by the Virtual File System (VFS). The system contains a parser subsystem that breaks down incoming RPC messages into their constituent parts. A typical usage scenario involves an RPC dispatcher receiving a `READLINK` request. The dispatcher uses this module's `args` function to extract the file handle from the request payload.

Inside the system, the following things happen and they use this module: The `args` function delegates the heavy lifting of reading and validating the file handle to the `file::handle` function. This ensures that the file handle adheres to the NFSv3 size constraints (64 bytes). Once validated, the handle is wrapped in `read_link::Args`. This structure is then passed to the VFS implementation (specifically the `ReadLink` trait), which uses the handle to locate the symbolic link on the storage backend and retrieve its target path. Without this module, the VFS layer would receive raw bytes instead of a structured argument, violating the separation of concerns between protocol parsing (XDR decoding) and file system logic.
