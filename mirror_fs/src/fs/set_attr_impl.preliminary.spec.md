## 2. Mechanics

### Mechanism 1: Implementation of `SetAttr` for `MirrorFS`

**Intent:**
To provide the concrete logic for modifying file attributes (metadata) within the `MirrorFS` backend, adhering to the NFSv3 protocol requirements. This includes resolving file handles to local paths, performing optimistic concurrency checks (guards), applying attribute changes, and reporting Weak Cache Consistency (WCC) data.

**Inputs:**
- `args: set_attr::Args`: Contains the file handle to modify, the new attributes to set, and an optional guard for synchronization.

**Outputs:**
- `Result<set_attr::Success, set_attr::Fail>`:
 - `Success`: Contains `wcc_data` reflecting the state of the object after the modification.
 - `Fail`: Contains an `error` and `wcc_data` reflecting the state of the object (which may be partially modified or unchanged).

**Steps:**
1. **Path Resolution**: The method calls `self.path_for_handle(&args.file).await` to translate the opaque NFS file handle into a concrete filesystem path.
 - If this fails, it returns `Err` with the specific error and empty `WccData` (before/after `None`).
2. **Metadata Retrieval**: It calls `Self::metadata(&path)` to fetch the current metadata of the object.
 - If this fails, it returns `Err` with the specific error and empty `WccData`.
3. **State Capture**: It captures the "before" state using `Self::wcc_attr_from_metadata` and the current full attributes using `Self::attr_from_metadata`.
4. **Guard Verification**: If `args.guard` is present, it compares the `ctime` of the current attributes with the `ctime` in the guard using `Self::same_time`.
 - If they differ, it returns `Err(set_attr::Fail)` with `vfs::Error::NotSync`. The `wcc_data` in this case includes the "before" attributes and the current attributes as "after".
5. **Attribute Application**: It calls `Self::apply_set_attr(&path, &args.new_attr)` to perform the actual modification on the filesystem.
 - If this fails, it returns `Err` containing the error and `WccData` generated by `Self::wcc_data` (which reads the post-attempt state).
6. **Success**: If all steps succeed, it returns `Ok(set_attr::Success)` containing `WccData` generated by `Self::wcc_data`.

**Edge Cases:**
- **Handle Resolution Failure**: If the file handle is invalid or stale, `path_for_handle` fails, and the operation aborts immediately.
- **Guard Mismatch**: If the file was modified by another client between the `GETATTR` and this `SETATTR`, the `NotSync` error is returned, and no attributes are changed.
- **Partial Failure**: If `apply_set_attr` fails partway through (e.g., changing size but failing on mode), the `Fail` result contains `WccData` that reflects the actual state on disk, allowing the client to detect partial modifications.

**Complexity:**
- **Time**: Dominated by filesystem I/O operations (path lookup, metadata read, attribute write). Logic overhead is O(1).
- **Space**: O(1) for storing metadata structures.

**Determinism:**
- **Non-deterministic**: Depends on the state of the underlying filesystem and the success of system calls.

## 7. Overview

This module is used in order to **provide the concrete implementation of the NFSv3 `SETATTR` procedure for the `MirrorFS` backend**. The system requires this module to bridge the gap between the abstract VFS interface (which defines *what* needs to happen—change attributes, check guards) and the concrete filesystem logic (which defines *how* it happens—resolving handles, reading/writing metadata).

The `MirrorFS` system is a specific filesystem backend that maps NFS operations to a local filesystem. This module is necessary because the generic `SetAttr` trait does not know how to interact with the specific internal state of `MirrorFS` (e.g., how to convert a `Handle` to a `Path`, or how to apply `NewAttr` to a local file).

A typical usage scenario involves a client sending an `SETATTR` request to truncate a file. The RPC layer deserializes the request into `set_attr::Args` and calls `MirrorFS::set_attr`. This implementation then:
1.  Uses `path_for_handle` to find the local file.
2.  Reads the current metadata to check if the file's `ctime` matches the client's `guard` (preventing race conditions).
3.  If valid, calls `apply_set_attr` to truncate the file and update other metadata.
4.  Reads the metadata again to construct `WccData`, which is sent back to the client so it can update its cache.

Inside the system, the following things happen and they use this module:
1.  **Handle Translation**: The module relies on `path_for_handle` (assumed to be defined in `super::MirrorFS`) to map the abstract NFS handle to a concrete path. This is critical because `MirrorFS` might use custom handle encoding.
2.  **Optimistic Locking**: The module implements the `guard` check logic defined in the `SetAttr` trait specification. By comparing `ctime` values, it ensures that the client is acting on the latest version of the file metadata, preventing lost updates.
3.  **State Reporting**: The module ensures that even if the operation fails (e.g., due to an I/O error during `apply_set_attr`), the client receives `WccData`. This allows the client to synchronize its cache with the server's state, even if the requested modification didn't fully succeed.

**Assumptions**:
- The module assumes the existence of several helper methods on `MirrorFS` or in its scope (`super`), which are not listed in the public facts but are used in the code:
 - `path_for_handle(&Handle) -> Result<Path, Error>` (async)
 - `metadata(&Path) -> Result<Metadata, Error>`
 - `wcc_attr_from_metadata(&Metadata) -> WccAttr`
 - `attr_from_metadata(&Metadata) -> Attr`
 - `same_time(Time, Time) -> bool`
 - `apply_set_attr(&Path, &NewAttr) -> Result<(), Error>`
 - `wcc_data(&Path, Option<WccAttr>) -> WccData` (likely reads current metadata to populate `after`)
- These helpers are assumed to handle the actual interaction with the OS filesystem (e.g., `std::fs::metadata`, `std::fs::set_permissions`).
